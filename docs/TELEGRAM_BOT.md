# Telegram Admin Bot

> **Служба:** `hydra-tg-admin` · **Доступ:** только Telegram user ID, указанный
> как Admin Chat ID

Бот — административный адаптер HYDRA. Он использует тот же `ApplicationService`,
что TUI и CLI, выполняет блокирующие операции вне asyncio event loop и не
дублирует lifecycle-логику плагинов.

## Настройка

Настраивается в TUI, раздел **Telegram**:

1. **Admin-токен** — создайте бота у [@BotFather](https://t.me/BotFather) и
   вставьте выданный токен.
2. **Admin Chat ID** — узнайте свой ID у
   [@userinfobot](https://t.me/userinfobot) и укажите его.
3. **Запустить Admin-бота** — HYDRA установит и запустит службу
   `hydra-tg-admin`.

Оба значения обязательны: без токена или без Chat ID запуск отклоняется.
Управлять службой можно и напрямую:

```bash
sudo systemctl status hydra-tg-admin
sudo systemctl restart hydra-tg-admin
sudo journalctl -u hydra-tg-admin -n 100 --no-pager
```

## Интерфейс

Команда `/start` или `/menu` открывает кнопочный Control Center:

```text
   /start · /menu
        │
        ├── Система ──────────── состояние VPS и служб
        │
        ├── AntiDPI ──────────┬─ протокольная и сетевая телеметрия
        │                     ├─ запуск / остановка          ⚠ подтверждение
        │                     └─ разбан IP                    ⚠ подтверждение
        │
        ├── Honeypot ─────────┬─ порт ловушки и её баны
        │                     ├─ запуск / остановка          ⚠ подтверждение
        │                     └─ разбан IP                    ⚠ подтверждение
        │
        ├── Fail2ban ─────────── сводка и подробности каждого jail:
        │                        ошибки, баны и политика
        │
        └── Уведомления ──────── независимые переключатели категорий
```

Действия, помеченные ⚠, требуют явного подтверждения нажатием.

Команды доступны и напрямую:

| Команда | Действие |
| :--- | :--- |
| `/start`, `/help`, `/menu` | Открыть Control Center |
| `/system`, `/status` | Состояние VPS и служб |
| `/antidpi` | Состояние и телеметрия AntiDPI |
| `/honeypot` | Состояние ловушки |
| `/fail2ban` | Сводка jails |
| `/notifications`, `/notify` | Настройки категорий уведомлений |
| `/unban <ip>` | Снять блокировку с адреса |

Изменение состояния защитных служб и разбан требуют подтверждения.

## Уведомления

Независимо переключаются master switch, AntiDPI, Honeypot, Fail2ban BAN, события
UNBAN и системные уведомления. Настройки атомарно сохраняются в state.

- Выключенная категория не выполняет HTTP-запрос к Telegram.
- Honeypot уведомляет только после подтверждённого успешного firewall-бана, а не
  при одном TCP connect.
- Статистика `attempted`, `delivered` и `failed` позволяет отличить отсутствие
  угроз от сбоя доставки.

### Кнопка блокировки в ALERT

Каждый AntiDPI ALERT содержит кнопку `🚫 Заблокировать`. Она применяет штатный
AntiDPI ipset-ban ко всему входящему трафику IP с прогрессивным TTL.

- Callback принимается только от настроенного администратора.
- Повторное нажатие не создаёт новый offense.
- Адрес из whitelist заблокировать через кнопку нельзя.
- После успеха исходный ALERT показывает `Action`, `TTL` и `Offense`, а кнопка
  удаляется.

Политики scoring и прогрессивных TTL описаны в [ANTIDPI.md](ANTIDPI.md).

## Безопасность

- IP валидируются и передаются внешним программам только как argv.
- Динамический текст экранируется для Telegram HTML.
- Токен не выводится при HTTP-ошибках.
- Тяжёлые status/systemd-операции выполняются вне asyncio event loop.
- Изменение состояния служб и снятие блокировок требуют подтверждения.
- Мониторы Fail2ban и Honeypot переживают logrotate и не воспроизводят старые
  события.

> [!CAUTION]
> Бот работает от `root`, а его токен является **root-equivalent секретом**. Не
> добавляйте бота в группы и перевыпустите токен при любом подозрении на
> компрометацию.
